# Adarsha Job Extraction — running this on another machine

Scrapes every Adarsha Samaj (Pokhara daily) e-paper issue from 2012→today, extracts job ads
from rendered page images, and stores them with dates, Nepali text, English translation and a
cropped image per ad.

**The model runs are driven by `opencode`, not a script.** `extract.py prep/prompt` renders the
images and prints the prompt; you (or your agent harness) run each page through
`opencode run`, and `extract.py ingest` loads the answers. There is no API key needed.

## 1. Requirements

```bash
brew install poppler                     # pdftoppm, pdftotext, pdfinfo
pip install -r automations/adarsha/requirements.txt
# requirements: anthropic httpx nepali-datetime opencv-python-headless pytest
```

`opencode` must be installed and authenticated, since it is the extraction backend.

## 2. Fix the paths in the database (do this first)

`data/adarsha.db` is committed, but it stores **absolute paths** from the machine that built it.
Rebind them to this checkout or nothing will open a crop or page:

```bash
python automations/adarsha/common.py --relocate
```

Idempotent, and safe to re-run. Add `--from /old/path/to/automations/adarsha` if the old root
cannot be inferred.

## 3. What you get, and what you do not

Committed (small, expensive to rebuild):

| Path | Size | What |
|---|---|---|
| `data/adarsha.db` | 4.6 MB | all tables: 4,708 issues, 4,648 pdfs, 218 jobs, triage, crops flags |
| `data/crops/` | 31 MB | one cropped image per ad — the actual deliverable |
| `data/cc/` | 432 KB | the per-page model answers, re-ingestable without re-running the model |
| `data/audit_cc.md` | 30 KB | the 30-job spot-check sheet, marked |
| `data/groundtruth.csv` | 1.6 KB | hand/vision ad counts for the recall check |
| `data/pilot_compare.md` | 0.4 KB | recall + era comparison |
| `data/vision_*.json` | 30 KB | cached vision-audit verdicts (resumable) |

Not committed, and regenerated by stage:

| Path | Size | Rebuild with |
|---|---|---|
| `data/pdfs/` | **19 GB** | `python automations/adarsha/download.py` |
| `data/pages/` | 320 MB | `python automations/adarsha/render.py` |
| `data/tiles/` | 430 MB | `python automations/adarsha/extract.py prep` |

The PDFs are not in git because 19 GB exceeds GitHub's limits. They come off the public web,
so they are re-downloadable. **Budget ~21 GB of disk before starting a full run.**

## 4. Run order

```bash
cd automations/adarsha

# a) discovery (already done and committed — issues + pdfs rows exist)
python discover.py

# b) download ~21 GB of PDFs into data/pdfs/<sha256>.pdf
python download.py --from 2026-08-30 --to 2026-09-30

# c) render 1000px page JPEGs for triage
python render.py --from 2026-08-30 --to 2026-09-30

# d) extraction — two steps, a model run in between
python extract.py prep  --run cc --from 2026-09-26 --to 2026-09-30
python extract.py prompt --pdf <pdf_id>      # prints one prompt for a whole issue
#    ... run each printed prompt through:  opencode run "<prompt>" -m <model>
#    ... the subagent writes data/cc/<run>/<pdf_id>-<page>.json
python extract.py ingest --run cc --model <model-id>

# e) audit
python audit.py report --run cc
python audit.py compare --runs cc
```

Every stage is resumable and skips completed rows.

## 5. Vision audit helpers (`vision_audit.py`)

Drives `opencode run` as a checker. All subcommands cache to `data/vision_<kind>.json`.

```bash
python vision_audit.py groundtruth --workers 3   # fill data/groundtruth.csv
python vision_audit.py spotcheck  --workers 3   # mark the 30 jobs in audit_cc.md
python vision_audit.py verify    --workers 4 --votes 3   # set jobs.crop_ok
python vision_audit.py reclass   --workers 4 --votes 3 --category training
```

**Use `--votes 3`, not the default.** A single vision sample is not reliable: the same crop
was judged matching on one call and mismatching on the next, and a single-sample pass produced
2 false "wrong crop" verdicts out of 30 that were correct when inspected by eye. Majority voting
fixed both problems.

## 6. Tests

```bash
cd automations/adarsha && pytest test_adarsha.py -q     # 22 tests
```

Covers the BS date parser (every observed title format and spelling), the legacy Preeti-font
masthead decoder, relative-deadline arithmetic, tile→page coordinate mapping, URL rewrite rules,
and merge/similarity logic.

## 7. Known limits — read before trusting the data

- **Triage recall is NOT established.** 6 of 6 sampled ad pages were caught, but only 6 of the
  15 sampled pages had ads, so the 95% lower bound is only **~61%**. The spec's gate is ≥95%.
  Settle this before a full run, or you may silently miss ad pages.
- **~6.0% of pilot rows are not job ads** (13/218, all `training` course catalogues and
  study-abrowad placement ads). They are flagged via `jobs.category_source = 'reclass:EXCLUDE'`,
  not deleted.
- **Crop accuracy is 99.1%** (216/218 ok, 2 bad rows = 1 ad), verified by 3-vote majority.
  `jobs.crop_ok` flags every row: 1 = crop matches, 0 = crop is a different ad, NULL = unchecked.
- **Counts are non-deterministic.** The same page yielded 10, 11 and 13 ads on three runs. The
  ground truth in `groundtruth.csv` is a *model* opinion, not a human one.
- **Single model, single run.** No Opus-vs-Sonnet comparison exists, so the cost decision the
  spec asks for cannot be made from this data.
- **Archive gaps:** 158 issues have dead PDF links, 481 have no PDF link at all.

## 8. Known blockers for a full run

- **Disk.** Tiles are 4.21 MB/page; all 23,595 pages needs **~99 GB**. Add 21 GB of PDFs and
  12 GB of page JPEGs. Free space first, and delete tiles per page as you go — nothing currently
  cleans them up.
- **Time.** Measured ~16 s for a small crop, ~4m43s for one cold full-resolution tile. A full
  pass is days of wall-clock, not hours.
